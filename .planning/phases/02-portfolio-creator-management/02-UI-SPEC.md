## Spacing Scale

Declared values (multiples of 4 — 8-point base):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between icon and label text, inline badge padding |
| sm | 8px | Gap between form field label and input; gap between sibling table cells |
| md | 16px | Default element spacing; card internal padding (horizontal); input padding |
| lg | 24px | Card internal padding (vertical); section gap within a tab panel |
| xl | 32px | Gap between header and content card; gap between tab panel sections |
| 2xl | 48px | Reserved (major section breaks — not used in Phase 2) |
| 3xl | 64px | Reserved (page-level spacing — not used in Phase 2) |

Exceptions:
- Touch targets: all interactive elements (`button`, `input`, clickable rows) must have `min-h-[44px]` — matches Phase 1 established pattern.
- Card padding: `p-8` (32px) on the outer content card, consistent with Phase 1 `dashboard/page.tsx`.
- Tab bar items: `px-4 py-2` (16px / 8px) matching the "Sign out" button pattern from Phase 1.
- Modal: `p-6` (24px) internal padding; `max-w-sm` width consistent with auth card precedent.

## Color

Phase 1 zinc dark theme — locked. No glassmorphism. No Electric Indigo palette yet (Phase 6).

| Role | Tailwind Class | Hex Approx | Usage |
|------|---------------|------------|-------|
| Dominant (60%) | `bg-zinc-900` | #18181b | Page background (`min-h-screen`) |
| Secondary (30%) | `bg-zinc-800 border border-zinc-700 rounded-xl` | #27272a / #3f3f46 | Content card, modal background, input background |
| Accent (10%) | `bg-indigo-500` / `text-indigo-400` | #6366f1 / #818cf8 | See reserved list below |
| Destructive | `text-red-400` | #f87171 | Delete confirmation text, error messages |

**Accent reserved for (exclusive list — no other elements use indigo):**
1. Primary action buttons: "Save", "Log", "Add Creator" (`bg-indigo-500 hover:bg-indigo-400`)
2. Active tab indicator: bottom border or background on the currently selected tab
3. Focus ring on all interactive elements (`focus:ring-2 focus:ring-indigo-500`)
4. Inline links (e.g. "Learn more" if any) (`text-indigo-400 hover:text-indigo-300`)

**Accent NOT used for:** secondary buttons, toggle states, row hover, table headers, form labels, status text.

**Secondary interactive states:**
- Hover row background: `hover:bg-zinc-700/50` (zinc surface shift, no indigo)
- Tracking toggle active (tracked): `text-indigo-400` label with checkmark text only — no indigo background fill
- Tracking toggle inactive: `text-zinc-400` label with "Track" text
- Secondary/ghost button (Cancel, Edit budget inline): `border border-zinc-700 text-zinc-300 hover:bg-zinc-800 hover:text-white`

## Interaction Contracts

### Tab Navigation

- Tab click → `router.push(?tab=[value])` — shallow routing, no full reload
- Active tab persists on page reload (driven by URL, not state)
- Default: if `?tab` absent → Portfolio tab active
- No animation on tab switch in Phase 2 (Framer Motion deferred to Phase 6)

### Holdings CRUD

- "Add Holding" button → modal opens (dialog overlay)
- Modal close: [Cancel] button, or pressing Escape, or clicking backdrop
- On [Save]: server action called → modal closes on success → holdings list re-renders (server component revalidation via `revalidatePath`)
- On validation error: modal stays open, inline error shown below field
- [Edit] on row → same modal pre-filled with existing values
- [Delete] on row → inline confirmation appears in-row (not a full modal): `"Delete VWRP? [Confirm] [Cancel]"` in `text-sm`; on [Confirm] → server action → row removed

### Monthly Budget Edit

- [Edit] → value text replaced by `<input type="number">` pre-filled with current value, with [Save] and [Cancel] inline
- [Save] → server action updates `monthly_budget` on `user_profiles` → reverts to display mode with new value
- [Cancel] → reverts to display mode with no change
- Input: `min-h-[44px]` touch target, focus ring indigo

### Creator Track Toggle

- [Track] → server action: insert `user_creators` row → button updates to "✓ Tracking" state
- [✓ Tracking] → server action: delete (hard delete) `user_creators` row → button returns to "Track" state
- No confirmation for untrack (re-tracking restores the row)
- Optimistic update encouraged: toggle state immediately, revert on error

### Add Custom Creator

- Form submit → server action: check if `channel_url` already in `creators`; if yes, link user to existing creator; if no, insert new `creators` row then insert `user_creators` row
- On success: form clears; new creator appears at bottom of curated list as tracked
- On error: inline error below URL field

### ISA Log Contribution

- Form submit → server action: insert `isa_contributions` with `tax_year` computed server-side from `contribution_date` using UK tax year logic (6 Apr boundary)
- On success: form clears; allowance summary updates; new row appears in log
- [Delete] on log row → inline confirmation: "Remove this contribution? [Remove] [Cancel]"
- On [Remove]: server action → row deleted → allowance summary recalculates

## Accessibility Contracts

- All form inputs: explicit `<label htmlFor>` binding (no placeholder-as-label)
- Modal: `role="dialog"` with `aria-modal="true"` and `aria-labelledby` pointing to heading
- Modal focus: trap focus inside modal while open; return focus to trigger element on close
- Buttons: all `<button type="button">` for non-submit; `<button type="submit">` for form submit
- Destructive confirmations: `role="alert"` on confirmation text
- Error messages: `role="alert" aria-live="polite"` (consistent with Phase 1 login pattern)
- Color-only distinction: never rely on color alone — use text labels alongside color states
- Min touch target: `min-h-[44px]` on all interactive elements (established Phase 1 pattern)
