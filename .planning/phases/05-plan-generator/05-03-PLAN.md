    Signature:
    ```typescript
    export async function upsertBuyList(result: PlanResult): Promise<ActionResult>
    ```

    Implementation:
    - Import `'use server'` at top of file
    - Auth: `const supabase = await createClient(); const { data: { user } } = await supabase.auth.getUser(); if (!user) return { error: 'Something went wrong. Please try again.' }`
    - Early return if `result.type !== 'buy-list'` — only persist full buy lists, return `{}` silently for no-strategy / no-fill-tickers states
    - Get current month string: `const month = new Date().toISOString().slice(0, 7)` (format: 'YYYY-MM')
    - Serialize items before JSONB insert (Pitfall 1 — Decimal not JSON-serializable):
      ```typescript
      const serializedItems = result.items.map(item => ({
        ticker: item.ticker,
        category: item.category,
        amount_gbp: item.amountGbp.toFixed(2),      // string, not Decimal
        allocation_gap_pct: item.allocationGapPct,
        rationale: item.rationale,
      }))
      ```
    - Write via service client (RLS bypass for upsert — same pattern as saveCreatorWeight):
      ```typescript
      const svc = createServiceClient() as any
      const { error } = await svc.from('buy_lists').upsert(
        {
          user_id: user.id,
          month,
          budget_gbp: result.effectiveBudget.toFixed(2),
          items: serializedItems,
          unified_allocation: {},   // placeholder — page.tsx will pass blended strategy in Wave 3
        },
        { onConflict: 'user_id,month' }
      )
      ```
    - `if (error) return { error: 'Something went wrong. Please try again.' }`
    - `revalidatePath('/dashboard')`
    - `return {}`

    **Action 2: `setFillTicker`**

    Signature:
    ```typescript
    export async function setFillTicker(holdingId: string, category: AssetCategory): Promise<ActionResult>
    ```

    Implementation per D-01 (05-CONTEXT.md) and research Pattern 5:
    - Auth: same getUser() pattern as all other actions
    - Validate: `if (!holdingId || !category) return { error: 'Something went wrong. Please try again.' }`
    - Use service client for both writes
    - Step 1: Clear any existing fill ticker for this user+category:
      ```typescript
      await svc.from('holdings')
        .update({ is_fill_ticker: false, updated_at: new Date().toISOString() })
        .eq('user_id', user.id)
        .eq('category', category)
        .eq('is_fill_ticker', true)
      ```
      (This clears old fill ticker before setting new one — prevents unique index violation)
    - Step 2: Set new fill ticker:
      ```typescript
      const { error } = await svc.from('holdings')
        .update({ is_fill_ticker: true, updated_at: new Date().toISOString() })
        .eq('id', holdingId)
        .eq('user_id', user.id)
      ```
      (`.eq('user_id', user.id)` scopes update to own holdings — defence-in-depth)
    - `if (error) return { error: 'Something went wrong. Please try again.' }`
    - `revalidatePath('/dashboard')`
    - `return {}`

    Imports needed at top of file:

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | setFillTicker holdingId | mitigate | `.eq('user_id', user.id)` on UPDATE scopes to user's own holdings — attacker cannot toggle another user's holding |
| T-05-03-02 | Elevation of Privilege | upsertBuyList user_id | mitigate | `user.id` from `getUser()` (server-authoritative) not from client payload — attacker cannot write to another user's buy_lists row |
| T-05-03-03 | Tampering | budget_gbp in upsertBuyList | mitigate | Wave 3 integration: server component re-reads monthly_budget from DB; effectiveBudget is computed server-side from DB values, not from unvalidated client input |
</threat_model>
