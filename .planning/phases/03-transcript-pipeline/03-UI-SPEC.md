# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Transcript Pipeline.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

Phase 3 adds NO new pages or routes. All UI lives inside the existing `/dashboard?tab=creators` view.
The existing `CreatorsTab` component is extended with three additions per tracked creator row:
1. A [Refresh] button (inline on the row)
2. A step status line below the row (visible only during/after refresh)
3. An expand/collapse toggle revealing a transcript list sub-table

## Component Specs

### 1. Creator Row Extension

The existing row from Phase 2 is extended. Do NOT redesign. Append to the right side and below.

**Before (Phase 2 row):**
```
[ Creator Name           ] [ channel URL ]        [ Track / ✓ Tracking ]
```

**After (Phase 3 extension):**
```
[ Creator Name           ] [ channel URL ]  [ ✓ Tracking ] [ Refresh ▶ ] [ ⌄ ]
  Last refreshed: 2 May 2026 at 14:23 (or "Never refreshed")
  ── Step status line (only visible during/after refresh) ──
```

Layout rules:
- [Refresh] button appended to the right of [✓ Tracking], before the expand toggle [⌄]
- Expand toggle [⌄] is the rightmost element
- "Last refreshed" timestamp sits below the creator name/URL block, `text-xs text-zinc-500`
- If `last_refreshed_at` is NULL, render: `text-zinc-600 text-xs` "Never refreshed"

**[Refresh] button spec:**
- Idle: `text-sm font-semibold text-white bg-indigo-500 hover:bg-indigo-400 rounded-md px-3 min-h-[36px] focus:outline-none focus:ring-2 focus:ring-indigo-500`
- Refreshing (active): spinner replaces button label. Spinner: 16px SVG circle, `animate-spin`, indigo-400. Button background stays `bg-indigo-500` at `opacity-75`. Button `disabled`.
- Disabled during peer refresh: NOT disabled — each row is independent (D-03)
- Not shown on un-tracked creators (only tracked creators have a Refresh button)

**Expand/collapse toggle spec:**
- Icon: chevron-down (14px inline SVG), `text-zinc-400 hover:text-zinc-200`
- Rotates 180deg when expanded: `transition-transform duration-200`
- `aria-expanded` boolean, `aria-controls` pointing to transcript list ID
- Min touch target: `min-h-[36px] min-w-[36px]` centered
- Only shown on tracked creators that have been refreshed at least once OR are actively refreshing

### 2. Step Status Line

Sits directly below the creator row (not inside a separate card). Visible only when `status === 'running'` OR `status === 'done'` with a summary, OR `status === 'error'`.

```
Fetching videos... 12/12
Embedding chunks... 8/12 videos
10/12 transcripts fetched, 2 pending retry   ← completion summary
YouTube API error — partial progress saved   ← error state
```

Spec:
- Container: `py-1 pl-1` (minimal padding, visually subordinate to creator row)
- Text: `text-sm text-zinc-400` for running steps
- Summary text (status = 'done'): `text-sm text-zinc-400`
- Error text (status = 'error'): `text-sm text-red-400`
- Disappears: on next user interaction with the row (expand toggle or new Refresh click) — or remains until page navigation. Does NOT auto-dismiss on a timer.
- No border, no background — plain text line only

Step label sequence (matches D-02):
1. `"Resolving channel..."`
2. `"Fetching videos... {n}/{total}"`
3. `"Fetching transcripts... {n}/{total}"`
4. `"Embedding chunks... {n}/{total} videos"`
5. On complete: `"{fetched}/{total} transcripts fetched{, N pending retry}" `  — omit trailing clause if 0 pending
6. On error: `"YouTube API error — partial progress saved"` (per D-05 approved copy)

### 3. Transcript List Sub-Table

Revealed by expand toggle. Renders below the step status line, within the creator row boundary.

**Structure:**
```
┌─────────────────────────────────────────────────────────────┐
│  TITLE                      PUBLISHED       STATUS          │
│  The 5 Best UK ETFs for...  12 Apr 2026     [Embedded]      │
│  How I Invest £500/month    28 Mar 2026     [Fetched]       │
│  Dividend Investing 2026    15 Mar 2026     [Pending]       │
└─────────────────────────────────────────────────────────────┘
```

Container: `bg-zinc-900/50 border border-zinc-700/50 rounded-lg mt-2 mb-1 overflow-hidden`

Column header row: `grid grid-cols-[1fr_auto_auto] gap-4 px-4 py-2 border-b border-zinc-700/50`
- Headers: `text-xs font-semibold text-zinc-400 uppercase tracking-wide`
- Columns: Title (flex-1), Published (fixed ~120px), Status (fixed ~90px)

Data rows: `grid grid-cols-[1fr_auto_auto] gap-4 px-4 py-2 border-b border-zinc-700/30 last:border-0`
- Title: `text-sm text-zinc-300 truncate` — single line, truncate with ellipsis
- Published date: `text-sm text-zinc-400 whitespace-nowrap` — format: "12 Apr 2026" (UK date format, no year if current year)
- Status chip: inline badge (see below)

**Status chips:**
- "Embedded": `inline-flex items-center px-2 py-0.5 rounded text-xs font-semibold bg-emerald-500/10 text-emerald-400 border border-emerald-500/20`
- "Fetched": `inline-flex items-center px-2 py-0.5 rounded text-xs font-semibold bg-indigo-500/10 text-indigo-400 border border-indigo-500/20`
- "Pending": `inline-flex items-center px-2 py-0.5 rounded text-xs font-semibold bg-zinc-700/50 text-zinc-400 border border-zinc-600/50`

Empty state (no transcripts yet — never refreshed): render sub-table container with single row: `text-sm text-zinc-500 px-4 py-3 italic` "No transcripts yet. Refresh to fetch."

Loading state (list loading after expand): `text-sm text-zinc-500 px-4 py-3` "Loading..."

Sort order: most recently published first (`publishedAt` DESC).

Scroll: if more than 8 rows, constrain to `max-h-64 overflow-y-auto` with scrollbar styled via Tailwind scrollbar utilities or default browser scrollbar.

## Interaction States

### Refresh Button State Machine

```
idle → [user clicks Refresh] → running → done | error
running → [poll returns done/error] → done | error
done → [user clicks Refresh again] → running
error → [user clicks Refresh again] → running
```

State is scoped per creator row. Other rows are unaffected (D-03).

### Polling Behavior (Client)

- Poll interval: 2000ms (`setInterval`) — per D-02, 2s suggested, executor may tune
- Polling starts on 202 response from POST
- Polling stops when GET returns `status === 'done'` or `status === 'error'`
- On stop: update step status line with summary or error copy
- If GET fails (network error): display `"Refresh failed — please try again"` and stop polling

### Expand/Collapse

- Toggle is client-only state — no API call on expand/collapse
- Transcript list is loaded once (with the tab data or on first expand) — not re-fetched on each toggle
- If transcripts have not been loaded yet for this row (initial dashboard load), fetch them on first expand via a client-side GET to a transcript list endpoint or pass initial data from server component

## Accessibility

- [Refresh] button: `type="button"`, `aria-label="Refresh {creatorName}"`, `disabled` during active polling
- Expand toggle: `type="button"`, `aria-expanded={boolean}`, `aria-controls="{creatorId}-transcript-list"`
- Transcript list container: `id="{creatorId}-transcript-list"`, `role="region"`, `aria-label="Transcripts for {creatorName}"`
- Step status line: `aria-live="polite"` (step updates are informational, not urgent)
- Error state: `role="alert"` with `aria-live="assertive"` (errors require user attention)
- Status chips: `aria-label` not required — chip text is self-describing
- Column headers in transcript list: `scope="col"` on `<th>` elements if rendered as `<table>`; if CSS grid, add `role="columnheader"` to header cells
