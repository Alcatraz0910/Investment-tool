## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07-01 | Information Disclosure | Cross-user transcript leak via .in('creator_id', tracked) query | mitigate | trackedIds is derived from `user_creators` filtered by `auth.uid()` (RLS) — only the current user's tracked creators reach the IN query. Transcripts table allows authenticated SELECT (creator-scoped, not user-scoped — per Phase 1 schema lines 217-220), but the bounded IN query prevents enumeration of unrelated creators' content from this surface |
| T-03-07-02 | Elevation of Privilege | Untracked creator's row exposes RefreshButton | mitigate | JSX guard `tracked.has(creator.id) && (...)` ensures RefreshButton/TranscriptList render only for tracked creators. Defence-in-depth: the API Route additionally verifies user_creators ownership (Wave 3) — UI-only guard is not load-bearing |
| T-03-07-03 | Tampering | page.tsx accidentally drops auth/redirect logic during edit | mitigate | Acceptance criterion: other tab branches and auth/redirect logic unchanged (verified via `git diff` review). Edits are ADDITIVE only |
| T-03-07-04 | Denial of Service | transcriptsByCreator query times out on huge transcript count | accept | One IN query per dashboard render; tracked-creator count bounded by user behavior (typically <20 creators); each transcript row is metadata only (raw_text included for chip status — could be optimized later by selecting only is_embedded + raw_text IS NULL) |
| T-03-07-05 | Information Disclosure | Banned vocabulary slipped into copy via integration | mitigate | Acceptance criteria for both files include explicit "no advice/recommend/suggest" check |
